# bas_competition

Код для задания по посадке дрона Pioneer на движущуюся платформу с маркером. По обновленному условию платформа TurtleBro движется сама, поэтому этот репозиторий отвечает только за две части:

- компьютерное зрение: найти маркер и передать смещение от центра кадра;
- управление дроном: взлет, поиск, наведение, посадка и программный `DISARM`.

TurtleBro запускать из этого репозитория не нужно.

> Важно: перед запуском на реальном дроне проверьте камеру, связь OpenMV с Pioneer, направление осей, знаки поправок и безопасную аварийную посадку.

## Что запускать на соревновании

Основной боевой вариант состоит из двух файлов:

| Файл | Где запускается | Назначение |
| --- | --- | --- |
| `openMV_script.py` | OpenMV IDE, на камере OpenMV | Распознает AprilTag `TAG36H11` и отправляет в Pioneer строку `FOUND,cx,cy,size` или `NONE`. |
| `pioneer_mission.lua` | Pioneer Station, на дроне | Управляет миссией: взлет, поиск, наведение, посадка, `DISARM`, LED-индикация и лог. |

Вспомогательные файлы:

| Файл | Назначение |
| --- | --- |
| `START_HERE.md` | Короткая памятка перед зачетной попыткой. |
| `mission_logger.py` | Дополнительный логгер на ноутбуке. Можно запускать отдельно, если нужен внешний лог. |
| `generate_marker.py` | Генерация ArUco-маркера `marker_id1.png` для локальной проверки OpenCV-скриптов. |
| `test_aruco_webcam.py` | Проверка распознавания маркера через веб-камеру ноутбука. |
| `vision.py` | OpenCV-детектор маркера для Python-прототипа. |
| `main_mission.py` | Python-прототип миссии с `MockPioneer`. Полезен для локальной отладки логики. |
| `drone_controller.py` | Обертка управления Pioneer для Python-прототипа. Сейчас использует `MockPioneer`. |
| `mock_pioneer.py` | Имитация дрона без подключения к железу. |

## Последовательность запуска

### 1. Подготовить маркер

Для OpenMV-версии используйте AprilTag семейства `TAG36H11`. Это штатный и самый надежный вариант распознавания на OpenMV.

Если проверяете только локальный OpenCV-прототип на ноутбуке, можно сгенерировать тестовый ArUco-маркер:

```bash
python generate_marker.py
```

Файл `marker_id1.png` можно открыть на телефоне или распечатать.

### 2. Запустить компьютерное зрение на OpenMV

1. Откройте OpenMV IDE.
2. Подключите OpenMV-камеру.
3. Откройте файл `openMV_script.py`.
4. Сохраните его на камеру как `main.py` или запустите через `Run`.
5. Поднесите AprilTag `TAG36H11` к камере.
6. Убедитесь, что при обнаружении маркера включается зеленый LED OpenMV.

OpenMV отправляет данные в Pioneer по UART в формате:

```text
FOUND,cx,cy,size
```

Если маркер не найден:

```text
NONE
```

Проверьте, что скорость UART в `openMV_script.py` совпадает со скоростью в `pioneer_mission.lua`: `115200`.

### 3. Загрузить миссию на Pioneer

1. Откройте Pioneer Station.
2. Подключитесь к дрону.
3. Откройте файл `pioneer_mission.lua`.
4. Загрузите скрипт на дрон.
5. Проверьте, что OpenMV подключена к нужному UART-порту.
6. Запустите скрипт.

Логика `pioneer_mission.lua`:

1. Дрон включает красный LED и взлетает на `TAKEOFF_HEIGHT`.
2. В режиме поиска мигает зеленым LED.
3. Читает данные от OpenMV.
4. При обнаружении маркера включает постоянный синий LED.
5. Корректирует положение по `cx`, `cy`.
6. Когда маркер по центру и достаточно крупный в кадре, выполняет посадку.
7. После посадки вызывает `pioneer.disarm()`.
8. Сохраняет лог в `mission_log.txt`.

### 4. Платформа TurtleBro

Ничего запускать не нужно. По обновленному заданию TurtleBro движется сам.

Перед стартом миссии достаточно убедиться, что маркер закреплен на платформе, хорошо виден сверху и не закрывается конструкцией.

### 5. Дополнительный логгер

Если нужен отдельный лог на ноутбуке, запустите в отдельном терминале:

```bash
python mission_logger.py
```

Логи сохраняются в папку `logs/`. Если `pioneer_sdk` недоступен, логгер все равно стартует в ручном режиме.

## Локальная проверка на ноутбуке

Этот путь нужен только для отладки OpenCV-прототипа без реального дрона.

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его на Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Или на Linux/macOS:

```bash
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Проверьте камеру ноутбука:

```bash
python test_aruco_webcam.py
```

Запустите Python-прототип миссии без реального дрона:

```bash
python main_mission.py
```

В этом режиме команды полета печатает `MockPioneer`, реальный дрон не используется.

## Настраиваемые параметры

В `pioneer_mission.lua`:

| Параметр | Смысл |
| --- | --- |
| `TAKEOFF_HEIGHT` | Высота взлета. |
| `SEARCH_HEIGHT` | Высота поиска маркера. |
| `APPROACH_HEIGHT` | Высота наведения перед посадкой. |
| `PIXEL_TO_METER` | Коэффициент перевода ошибки в пикселях в команду движения. Требует подбора. |
| `DEAD_ZONE_PX` | Допуск по центру кадра. |
| `SIZE_CLOSE` | Размер маркера в пикселях, при котором дрон считает, что он достаточно близко для посадки. |
| `UART_BAUD` | Скорость UART между OpenMV и Pioneer. |

В `openMV_script.py`:

| Параметр | Смысл |
| --- | --- |
| `TAG_FAMILY` | Семейство AprilTag. Сейчас используется `image.TAG36H11`. |
| `TARGET_TAG_ID` | `-1` принимает любой ID; число вроде `0` или `1` ограничивает распознавание конкретным тегом. |
| `MIN_TAG_SIZE_PX` | Минимальный размер тега в кадре. |
| `MIN_DECISION_MARGIN` | Минимальная уверенность распознавания. Для первого теста стоит `0.0`. |
| `MAX_HAMMING` | Допустимое число исправленных битовых ошибок. Для первого теста стоит `4`, для полета можно ужесточить до `0-1`. |

## Проверка перед зачетной попыткой

1. OpenMV распознает AprilTag `TAG36H11` и отправляет `FOUND,cx,cy,size`.
2. Pioneer получает данные по UART.
3. Красный LED включается при взлете.
4. Зеленый LED мигает при поиске.
5. Синий LED горит постоянно при обнаружении и посадке.
6. При смещении маркера вправо/влево дрон двигается к маркеру, а не от него.
7. После посадки вызывается программный `DISARM`.
8. Лог миссии сохраняется.

## Безопасность

- Первые проверки делайте без винтов или в безопасном режиме, если это позволяет платформа.
- Не запускайте миссию на реальном дроне без проверки OpenMV и UART.
- Проверьте знаки коррекции `cx`, `cy` на малой высоте.
- Держите ручной аварийный сценарий посадки готовым до старта.
- Не полагайтесь на текущие значения `PIXEL_TO_METER`, `DEAD_ZONE_PX` и `SIZE_CLOSE` без тестов на реальном стенде.
