# bas_competition

Прототип кода для соревнований по беспилотным авиационным системам: дрон должен найти ArUco-маркер на движущейся платформе, выйти над центром маркера и выполнить посадку.

Проект разделен на три части:

- управление дроном Pioneer;
- компьютерное зрение для поиска маркера;
- управление движущейся платформой TurtleBro через ROS.

> Важно: текущая версия рассчитана на предварительную отладку. Перед запуском на реальном дроне обязательно проверьте параметры камеры, размер маркера, направление осей и поведение команд движения на безопасной площадке.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `main_mission.py` | Главный сценарий миссии: взлет, поиск маркера, центрирование, снижение и посадка. |
| `drone_controller.py` | Обертка над управлением дроном. Сейчас использует `MockPioneer`; для реального дрона нужно переключить импорт на `pioneer_sdk.Pioneer`. |
| `vision.py` | Детектор ArUco-маркера через OpenCV. Возвращает смещение маркера от центра кадра и примерную дистанцию. |
| `generate_marker.py` | Генерирует маркер `marker_id1.png` с ArUco `DICT_4X4_50`, `ID=1`. |
| `marker_id1.png` | Готовый маркер для печати или показа на экране. |
| `test_aruco_webcam.py` | Быстрая проверка распознавания маркера через веб-камеру ноутбука. |
| `mock_pioneer.py` | Имитация Pioneer SDK для проверки логики без подключения к дрону. |
| `turtlebro_mover.py` | ROS-скрипт для движения TurtleBro по кругу или квадрату через топик `/cmd_vel`. |
| `requirements.txt` | Черновой список зависимостей и команд установки. |

## Логика миссии

1. Дрон взлетает на высоту поиска `SEARCH_ALTITUDE`.
2. Камера ищет ArUco-маркер `ID=1`.
3. Если маркер не найден, дрон выполняет простой паттерн поиска: зависает в центре зоны.
4. Если маркер найден, включается зеленое мигание LED.
5. По смещению маркера от центра кадра считается поправка в локальных координатах.
6. Когда маркер примерно по центру, дрон постепенно снижается, продолжая корректировать положение.
7. После снижения выполняется посадка.
8. Если маркер не найден за `60` секунд, запускается аварийная посадка.

## Быстрый старт без дрона

Создайте и активируйте виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate
```

На Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установите зависимости для локальной проверки зрения и mock-запуска:

```bash
pip install opencv-contrib-python numpy
```

При необходимости установите Pioneer SDK:

```bash
pip install pioneer-sdk
```

Сгенерируйте маркер:

```bash
python generate_marker.py
```

Проверьте распознавание через веб-камеру:

```bash
python test_aruco_webcam.py
```

Откройте `marker_id1.png` на телефоне или распечатайте его, покажите в камеру. Для выхода из окна OpenCV нажмите `q`.

Запустите основную миссию в режиме имитации:

```bash
python main_mission.py
```

В текущем состоянии `drone_controller.py` импортирует `MockPioneer`, поэтому команды полета будут печататься в консоль без обращения к реальному дрону.

## Запуск с реальным Pioneer

В `drone_controller.py` переключите импорт:

```python
from pioneer_sdk import Pioneer
# from mock_pioneer import MockPioneer as Pioneer
```

Перед полетом проверьте:

- дрон подключается через Pioneer SDK;
- `arm()`, `takeoff()`, `go_to_local_point()` и `land()` соответствуют используемой версии SDK;
- локальная система координат совпадает с направлением камеры;
- знак поправок `dx` и `dy` в `main_mission.py` не уводит дрон от маркера;
- высоты `SEARCH_ALTITUDE`, `APPROACH_ALTITUDE`, `LANDING_ALTITUDE` подходят под регламент и площадку.

## Запуск движущейся платформы TurtleBro

Скрипт `turtlebro_mover.py` публикует команды скорости в ROS-топик `/cmd_vel`.

Запуск движения по кругу:

```bash
python turtlebro_mover.py
```

По умолчанию используется:

- радиус: `1.5` м;
- скорость: `0.08` м/с;
- движение по кругу через `move_circle()`.

Для альтернативного движения можно вызвать `move_square()` из Python-кода или изменить блок:

```python
if __name__ == '__main__':
    move_circle(radius=1.5, speed=0.08)
```

ROS-зависимости (`rospy`, `geometry_msgs`) обычно должны быть установлены в окружении TurtleBro или ROS Noetic.

## Настраиваемые параметры

Основные параметры миссии находятся в `main_mission.py`:

| Параметр | Значение сейчас | Смысл |
| --- | --- | --- |
| `SEARCH_ALTITUDE` | `1.5` | Высота поиска маркера. |
| `APPROACH_ALTITUDE` | `0.8` | Высота наведения перед посадкой. |
| `LANDING_ALTITUDE` | `0.3` | Высота начала посадочного этапа. |
| `PIXEL_DEAD_ZONE` | `30` | Допуск в пикселях: маркер считается в центре. |
| `PIXEL_TO_METER` | `0.003` | Примерный коэффициент перевода ошибки из пикселей в метры. Требует подбора. |

Параметры зрения находятся в `vision.py`:

| Параметр | Значение сейчас | Смысл |
| --- | --- | --- |
| `camera_index` | `0` | Индекс камеры OpenCV. |
| `target_id` | `1` | ID отслеживаемого ArUco-маркера. |
| `marker_size` | `0.30` | Реальный размер стороны маркера в метрах. |
| `focal_length` | `600` | Приближенное фокусное расстояние в пикселях для оценки дистанции. |

## Калибровка перед соревнованиями

Минимальный список проверок:

- распечатать маркер без искажений и измерить фактическую сторону;
- записать фактический размер в `vision.py` (`marker_size`);
- проверить, что камера видит маркер при ожидаемой высоте полета;
- подобрать `focal_length` для более точной оценки дистанции;
- подобрать `PIXEL_TO_METER` на реальной высоте и с реальной камерой;
- проверить знаки `dx` и `dy`: при смещении маркера вправо/влево дрон должен двигаться к маркеру, а не от него;
- проверить поведение при потере маркера во время снижения;
- отдельно протестировать аварийную посадку.

## Безопасность

- Не запускайте основную миссию на реальном дроне без предварительного mock-теста и теста камеры.
- Первые проверки делайте без винтов или в безопасном режиме, если это позволяет платформа.
- Используйте ограниченную скорость платформы TurtleBro.
- Держите ручной аварийный сценарий посадки готовым до старта миссии.
- Не полагайтесь на текущий `PIXEL_TO_METER` без подбора на реальном стенде.

## Текущие ограничения

- В миссии используется простой P-подобный регулятор без фильтрации и предсказания движения платформы.
- Дистанция до маркера оценивается приблизительно по ширине маркера в кадре.
- При потере маркера во время снижения нет отдельной стратегии восстановления, кроме продолжения цикла с последними командами.
- `requirements.txt` сейчас больше похож на заметку с командами установки, чем на строгий pip-файл.
- Комментарии в некоторых `.py` файлах могут отображаться некорректно из-за кодировки, но структура кода читается.

## Типичный порядок проверки

1. Сгенерировать или открыть `marker_id1.png`.
2. Проверить маркер через `test_aruco_webcam.py`.
3. Запустить `main_mission.py` с `MockPioneer`.
4. Проверить движение TurtleBro отдельно через `turtlebro_mover.py`.
5. Переключить `drone_controller.py` на реальный `Pioneer`.
6. Провести короткие тесты на безопасной высоте с неподвижным маркером.
7. Провести тесты с медленно движущейся платформой.
